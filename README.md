# License Plate Detection & Recognition Pipeline

An end-to-end, two-stage pipeline that takes a vehicle image and returns the plate text:

```
image ──► YOLOv8n detector ──► padded crop ──► EasyOCR ──► rule-based cleaning ──► "06 ABC 123"
```

The assessed skill is the hand-off between the two models. The detector's bounding boxes, taken straight from model output, are the only input the OCR stage receives. No coordinates are hand-drawn anywhere in the pipeline.

## Usage

```python
from ultralytics import YOLO
import easyocr
from pipeline import read_plates, format_plate

det = YOLO("best.pt")
reader = easyocr.Reader(["en"])

for r in read_plates("car.jpg", det, reader):
    print(r["box"], r["conf"], r["raw"], "->", format_plate(r["text"]), r["valid"])
```

`read_plates()` returns one dict per detected plate. It returns an empty list when nothing is detected, and one entry per plate when an image contains several vehicles.

## Tools used and why

| Stage | Choice | Reason |
|---|---|---|
| Detector | **Ultralytics YOLOv8n**, fine-tuned (30 epochs, 640 px, T4 GPU) | Fine-tuning takes minutes, and it handles angled and distant plates far better than a Haar cascade. The nano model is fast enough for video. |
| Training data | Roboflow Universe *License Plate Recognition* dataset, v11, about 10k images, CC BY 4.0 | Large, single class (`License_Plate`), and exports directly in YOLOv8 format |
| Test data | **My own [N] photos** of cars in [location], hand-labeled in Roboflow | A held-out, local test set the detector never saw during training |
| OCR | **EasyOCR** (main), Tesseract (comparison) | EasyOCR installs with pip only. Tesseract was installed with `apt-get` inside Colab. |
| Environment | Google Colab (Linux + T4 GPU) | Free GPU for training |

### Escape hatches used
- **Tesseract path issues on Windows:** avoided by running in Colab (Linux), where `apt-get install tesseract-ocr` puts the binary on PATH, so `pytesseract.pytesseract.tesseract_cmd` does not need setting.
- **Label-format mismatch:** both datasets were exported from Roboflow in **YOLOv8 format** (normalized `class cx cy w h`), and the notebook converts these to pixel `x1,y1,x2,y2` for IoU. Roboflow's relative paths in `data.yaml` are rewritten as absolute paths. Roboflow's renamed files (`IMG_1234_jpg.rf.<hash>.jpg`) are mapped back to `IMG_1234` to match the ground-truth CSV.

## Pipeline details

1. **Detection:** YOLOv8n with a confidence threshold of 0.25. Every box above the threshold is kept, sorted by confidence.
2. **Cropping:** 10% padding on each side, clamped to the image borders, so characters at the plate edge are not cut off. Empty crops are skipped.
3. **OCR preprocessing:** grayscale, then upscaling to about 100 px height (cubic), then a bilateral filter that removes noise while keeping character edges. EasyOCR uses an A–Z / 0–9 allowlist and sorts text fragments left to right. Tesseract additionally uses Otsu binarization and `--psm 7` (single line).
4. **Text cleaning (Turkish format):**
   - Strip spaces and symbols, uppercase, and drop the `TR` country code from the blue EU strip.
   - Positions 1–2 are the province code and must be digits, so `O→0`, `I→1`, `B→8`, `S→5`, `Z→2`, `G→6`.
   - Every legal letter/digit split is tried. Letter positions get the reverse mapping (`0→O`, `1→I`, `8→B`, `5→S`), and digit positions get the digit mapping. The pipeline keeps the candidate that is a valid plate and needs the fewest substitutions.
5. **Format validation (bonus regex):**
   ```
   ^(0[1-9]|[1-7][0-9]|8[01])([A-Z][0-9]{4}|[A-Z]{2}[0-9]{3,4}|[A-Z]{3}[0-9]{2,3})$
   ```
   This matches a province code from 01 to 81, followed by one letter and 4 digits, two letters and 3–4 digits, or three letters and 2–3 digits.

## Evaluation method

- **Detection:** each ground-truth box is matched to the unused prediction with the highest IoU. Unmatched ground-truth boxes score IoU = 0, and unmatched predictions count as false positives.
- **OCR:** the cleaned text of the matched prediction is compared with the ground-truth string, using exact match and CER (Levenshtein distance / ground-truth length). A missed plate counts as wrong, so the accuracy is **end-to-end**, not OCR-only.

## Failure case analysis

Each failure is attributed to one stage. Crop measurements (Laplacian variance for blur, crop height, aspect ratio for angle, pixel standard deviation for contrast) support the explanation. See notebook section 7 for the images.

|---|---|---|---|---|

| 2 | [IMG_yyyy] | OCR | [34 BK 812 → 34 BK 612] | [e.g. motion blur (Laplacian var 45), 8 read as 6; both are digits, so the position rules cannot fix it] |
| 3 | [IMG_zzzz] | OCR | [06 AF 1234 → 06 A 1234] | [e.g. glare over the letters, one character dropped] |

**Patterns:**
- Position-based cleaning fixes letter/digit confusions (O/0, I/1, B/8) but cannot fix a digit misread as another digit (3 vs 5, 6 vs 8) or a dropped character.
- The detector is strongest on frontal, well-lit plates. Most misses are small or far-away plates, steep angles, and occlusion.

## Limitations and next steps

- OCR is the weaker stage. A plate-specific recognizer (for example a CRNN or PARSeq fine-tuned on Turkish plates) would fix confusions between digits.
- Two-row plates (motorcycles, some trucks) are not handled by the single-line cleaning rules.
- Perspective correction of angled crops (4-point warp) before OCR would help with steep angles.
